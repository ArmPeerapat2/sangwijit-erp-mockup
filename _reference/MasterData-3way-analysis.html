🔑 5 Pattern สำคัญ (ข้ามทุก master)

  1. create/update ผ่าน standard API ได้เต็มทั้ง 3 entity (GET/POST/PATCH/DELETE) — ไม่มี master read-only
  2. กลุ่ม/ประเภท/8 มิติ = defaultDimensions entity (Thai group → BC Dimension) → ตรงกับ decision "BC dropdown" · พอร์ทัลอ่าน/ผูกค่า ไม่สร้าง field เอง
  3. standard ไม่มีเสมอ = Thai localization + tracking: สาขาภาษี (TaxBranch) · unit ratio ต่อ item · serial/lot → ต้อง table extension + custom API page ใหม่ (standard API page extend field ไม่ได้ · ODataKeyFields=SystemId)
  4. "เครดิตวัน" = Payment Terms (FK) ไม่ใช่ตัวเลข → พอร์ทัลต้องแปลง
  5. ก่อน implement จริงต้องดึง $metadata ของ environment (field เปลี่ยนตาม version + custom)

สถาปัตยกรรม (4 ชั้น)

พอร์ทัล upload→ resize / thumbnail / virus scan→ Azure Blob Storage (public / private bucket)→ บันทึก reference (URL/path + metadata)
  1. External object storage = Azure Blob Storage (BC อยู่ Azure อยู่แล้ว · หรือ S3-compatible) — เก็บไฟล์จริง
  2. CDN หน้า public bucket — เว็บ/แอปดึงรูปสินค้าเร็ว + cache
  3. Reference table (portal DB หรือ BC custom table) — {id · entityType(item/customer/vendor/promo) · entityId · fileType(image/video/doc) · url/blobPath · filename · size · uploadedBy · date · tags · isPublic · version · sortOrder}
  4. Access: public media = CDN URL ตรง · private doc = signed URL (SAS token) หมดอายุ + เช็ค RBAC ก่อนออก token

รูปสินค้า → เว็บต่อ (e-commerce reuse)

  • URL คงที่ต่อ item (เช่น cdn/products/{itemNo}/1.jpg) · gallery หลายรูป (จัด sortOrder · รูปหลัก/รอง)
  • API สินค้าคืน array ของ image URL + video URL → เว็บ/แอป e-commerce render ตรง ไม่ต้องดึงจาก ERP
  • วิดีโอ: เก็บไฟล์ + poster thumbnail · embed ผ่าน URL (หรือฝัง YouTube/Vimeo แล้วเก็บแค่ลิงก์ ถ้าไม่อยาก host เอง)
  • หลายขนาด: gen thumbnail/medium/full ตอน upload → เว็บเลือกใช้ตามที่ (list ใช้ thumb · หน้า detail ใช้ full)

เอกสารสแกน (สัญญา/จดทะเบียน/ส่งเสริมการขาย)

  • แนบกับ record (ลูกค้า/vendor/promo) · private bucket · เข้าถึงผ่าน signed URL + RBAC (ใครดูได้ตามสิทธิ์)
  • version + audit: เก็บประวัติ (สัญญาเวอร์ชันใหม่ไม่ทับเก่า) · log ใคร upload/ดู/ดาวน์โหลด เมื่อไหร่ (เอกสารกฎหมาย/ภาษีต้อง trace ได้)
  • tag/หมวด: จดทะเบียนภาษี · สัญญา · หนังสือมอบอำนาจ · โปรโมชัน — filter ได้
  • OCR-ready (อนาคต): เก็บ text ที่ OCR ได้ → ค้นในเอกสารได้ (optional phase หลัง)

💡 ข้อเสนอ: shared component swt-media (1 ตัวใช้ทุกที่)

ตอนนี้มี pattern แนบไฟล์กระจายหลายที่ (sv1 audit-scan · po2 evidence · WH-5 photo · item image) → รวมเป็น component เดียว swtRenderMedia(el, {entity, entityId, type:'image|video|doc', public, maxFiles}):
  • upload (drag-drop) · preview grid (thumbnail) · จัดลำดับ (รูปหลัก) · ลบ · version (doc)
  • image/video = โหมด gallery (public) · doc = โหมด attachment (private + version + audit)
  • ทุกหน้าที่ต้องแนบเรียกใช้ตัวเดียว (item master · md2 ลูกค้า · vendor · pm promo · WH-5 · sv) — เหมือน swt-payment/swt-master-editor
ไม่ทำ: เก็บ base64/binary ใน BC field หรือ portal DB · แชร์ไฟล์ private ผ่าน URL ถาวร (ต้อง signed+หมดอายุ) · โยนไฟล์ใหญ่ผ่าน BC API (ช้า+limit)
