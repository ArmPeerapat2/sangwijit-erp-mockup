SL

งานขาย

7/7 ✦ ครบ
คุมวงจรขายตั้งแต่เสนอราคา → จอง → มัดจำ → บิลขาย → รับชำระ → ลดหนี้ · เป็นศูนย์ยืนยันลูกค้า + ตรวจวงเงินเครดิต + คิด VAT

เมนู / หน้าจอ

SL-Q คิวขาย (งานค้างรอทำ)
SL-1 ใบเสนอราคา
SL-2 ใบจอง (= BC Sales Order)
SL-3 ใบมัดจำ
SL-4 บิลขาย / ขายสด
SL-CN ใบลดหนี้ขาย
SL-F1 ขออนุมัติวงเงิน

Use case จริง

  1. ลูกค้าถามราคา → เสนอราคา → ตกลง → จองสต็อก
  2. จอง + จ่ายมัดจำ → ส่งของครบเงื่อนไข → ออกบิลขาย
  3. วงเงินไม่พอ → ระบบเตือน → ขออนุมัติวงเงิน (ตามชั้น)
  4. ขายสด → รับเงินหลายวิธี + โปรฯ อัตโนมัติ + ออกใบกำกับ
  5. ลูกค้าคืนสินค้า/ราคาผิด → ออกใบลดหนี้ (อ้างบิลต้นทาง)

คำตอบ / กติกาสำคัญ

  • Serial ไม่บังคับที่ขาย — ไปลงที่คลัง (WH เบิก) เท่านั้น
  • VAT 3 แบบต่อบิล — รวม / ไม่รวม / ไม่แสดง (แต่คิดลดก่อน VAT เสมอ)
  • ตรวจวงเงินทุกครั้ง — เกิน → เข้า SL-F1 ตามชั้น (0-50K / 50-200K / 200-500K / >500K)
  • Maker ≠ Checker — คนเปิดเอกสารอนุมัติตัวเองไม่ได้
  • ใบลดหนี้ต้องอ้างบิล — ไม่มีบิลต้นทาง = ออกไม่ได้

PO

งานจัดซื้อ

9 ✦
สั่งซื้อสินค้า · เจรจาส่วนลด/โปรฯ คู่ค้า · บันทึกข้อตกลงงบ · ตั้งหนี้เจ้าหนี้ · ติดตามเงินคืน (Trade Support) จาก Vendor

เมนู / หน้าจอ

PO-Q คิวจัดซื้อ (เตือนของใกล้หมด)
PO-1 ใบขอซื้อ (PR)
PO-2 ข้อตกลงงบ Vendor (MOU/Sell-in/out/Co-op)
PO-3 ใบวางบิล Vendor
PO-4 ใบสั่งซื้อ (PO)
PO-6 ใบตั้งหนี้เจ้าหนี้ (AP)
PO-7 สรุปได้จริง (Rebate/Trade Support)
PO-8 บิลฝาก (Deposit Pool)
PO-CN ใบลดหนี้เจ้าหนี้

Use case จริง

  1. ของใกล้หมด (MOS ≤2 เดือน) → เปิด PR → อนุมัติ → แปลงเป็น PO
  2. ตกลง MOU กับ Vendor (เป้า/Rebate/ระยะ) → บันทึก PO-2 → Vendor เซ็น
  3. ของส่งไม่ครบแต่ครบกำหนดจ่าย → ใช้บิลฝาก (PO-8) จ่ายก่อน
  4. Sell-in ลด% บนบิล → PO-4 สั่ง → PO-6 ตั้งหนี้หักทันที
  5. ถึงเป้า MOU → ขอ CN จาก Vendor → PO-7 Realize → หัก AP

คำตอบ / กติกาสำคัญ

  • ลด% บนบิล (Case 4) ดีสุด — ประหยัด VAT กว่าลดหลังบิล
  • "ตั้งหนี้" ต่างกัน — PO-2/PO-7 = บันทึกงบ (ไม่มีภาษี) · PO-6 = ตั้งหนี้จริง (มีภาษี)
  • กติกา MOS — ≤2 เดือนต้องสั่ง · ≤4 โอเค · >4 ห้ามสั่ง
  • Sanction Flow — Vendor ไม่ส่ง CN: เตือน Day-0 → Day-7 → Day-15 หยุดออก PO
  • จ่ายเงินจุดเดียว — Record Payment ที่ PO-7 เท่านั้น (กัน GL ซ้ำ)

WH

งานคลังสินค้า

9 ✦ ครบโมดูล
รับสินค้าจาก Vendor · เบิกจ่ายให้ขาย · โอนระหว่างคลัง · นับสต็อก · คุม Serial + Bin ทุกการเคลื่อนไหว

เมนู / หน้าจอ

WH-Q คิวคลัง (Q1 รับ / Q2 เบิก)
WH-1 ใบรับสินค้า (GRN + รับโอน)
WH-2 ใบเบิกจ่ายขาย (+2R ขอเบิก)
WH-3 ใบโอนสินค้า (+3R ขอโอน)
WH-4 ใบนับสต็อก (+4R เตรียมนับ)
WH-R Stock Card / รายงาน

Use case จริง

  1. Vendor ส่งของตาม PO → รับเข้า ใส่ Serial ทีละชิ้น + Bin → Post
  2. ขาย 5 ชิ้น → Waterfall: เบิกคลัง A → ไม่พอขอโอน B → ยังขาดค่อยซื้อ
  3. เบิกขาย → ใส่ Serial ต่อบรรทัด → พิมพ์ใบหยิบ → ยิงยืนยัน → ตัดสต็อก
  4. โอนคลัง → ส่งออก (In Transit) → ปลายทางรับเข้า → สต็อกอัปเดต
  5. นับสต็อกรายเดือน → ยิงนับของจริง → Manager ยืนยัน → ปรับ BC

คำตอบ / กติกาสำคัญ

  • Serial บังคับที่คลัง — รับเข้าต้องใส่ · เบิกออกต้องใส่ (ไม่ใช่ที่บิลขาย)
  • Waterfall — 1 บรรทัดขาย แตกได้ 3 ใบขอ (เบิก/โอน/ซื้อ) อ้างกลับขายใบเดียว
  • SLA — รับของ ≤4 ชม. · เบิกขาย ≤2 ชม. · โอน ≤1 วันทำการ
  • QC Hold — ของไม่ผ่าน → เข้า Location Hold อัตโนมัติ
  • ล็อกช่วงนับ — นับสต็อก item ไหน ล็อกการเคลื่อนไหว item นั้น

บัญชี / การเงิน

5 ✦
รับ-จ่าย · ลูกหนี้-เจ้าหนี้ · กระทบยอดธนาคาร · ค่าใช้จ่าย · ภาษีขาย/ซื้อ · ภาษีหัก ณ ที่จ่าย · บัญชี 2 เล่ม

เมนู / หน้าจอ

FI-Q คิวการเงิน (AR/AP/Aging)
FI-1 รับชำระลูกหนี้ (+1Q Apply)
FI-2 จ่ายชำระเจ้าหนี้ (+ WHT auto)
FI-3 กระทบยอดธนาคาร

Use case จริง

  1. ลูกค้าโอนเงิน → เข้าคิว Apply → จับคู่ Invoice อัตโนมัติ → ปิด
  2. ครบกำหนดจ่าย Vendor → เลือก Invoice → หัก WHT อัตโนมัติ → เข้าคิว FI-12
  3. ปลายเดือน → นำเข้า Statement เทียบ BC → จับคู่ → สร้าง JV ปรับ
  4. ปิดภาษีรายนิติบุคคล → เลือก Tag → โอนห้องภาษี → ออก ภ.พ.30
  5. สินทรัพย์ถาวร → สร้างการ์ด → รันค่าเสื่อมรายเดือน

คำตอบ / กติกาสำคัญ

  • Dual-Book Entity Tag — ทุกบิลซื้อติด Tag (1/2/3/novat) ว่าบริษัทไหนออกใบกำกับ → กรองเข้าห้องภาษี
  • WHT คิดอัตโนมัติ — ตอนจ่าย (FI-2) หัก 1-5% ตามหมวด Vendor
  • WHT ออกใบที่เดียว — สร้างค้างได้หลายที่ แต่ Release + พิมพ์ที่ FI-12 เท่านั้น
  • กระทบยอดก่อนปิดงวด — ทุกเดือน ก่อนล็อก posting ย้อนหลัง
  • เกินวงเงิน = ล็อก — ลูกค้าเกิน → สร้าง SO ไม่ได้จนขออนุมัติ

Use case จริง

  • เคลม 2 ทาง — ซ่อมได้ = จบใน SV · ซ่อมไม่ได้ = ส่ง Vendor → PO-CN / คืนเงิน

เมนู / หน้าจอ

MD-1 ทะเบียนสินค้า ✦ (BC365)
MD-2 ทะเบียนลูกค้า
MD-3 ทะเบียน Vendor ✦
MD-4 ทะเบียนพนักงาน
MD-5 สาขา & คลัง
MD-6 ทะเบียนเครื่อง (Service Item) ✦

Use case จริง

  1. ลูกค้าใหม่ → สร้าง + ตรวจ Tax ID + ที่อยู่ 3 แบบ + วงเงิน → ใช้ SO ได้
  2. สินค้าใหม่ → ตั้งรหัส/หมวด/ต้นทุน/Barcode + จุดสั่งซ้ำ
  3. Vendor ใหม่ → ตั้ง Tax ID/Bank/หมวด WHT → Finance ตรวจ → ใช้ PO ได้

คำตอบ / กติกาสำคัญ

  • ที่อยู่ 3 แบบ (ลูกค้า) — ออกใบกำกับ + จัดส่ง + ตามบัตร (บังคับสำหรับนิติบุคคล)

  • Blocked = ล็อกอัตโนมัติ — สร้าง SO/PO ไม่ได้จนปลด
  • ต้นทุนซ่อนจาก Sales — ผ่าน field permission

ออกแบบราคา · ส่วนลด · โปรโมชั่น · โควตา · เครื่องจำลองราคา → ป้อนให้ SC9 ที่ทุกหน้าขาย/บริการดึงไปใช้

เมนู / หน้าจอ

PM-Q แดชบอร์ดโปรฯ (โปรที่ active/ใกล้หมด)
PM-1 Price List (ราคาขายตามลูกค้า/สินค้า)
PM-2 โปรโมชั่น (%/บาท/แถม/Bundle)
PM-3 ส่วนลดขั้นบันได + Bundle
PM-4 โควตาขาย (เป้า + งบส่วนลด)
PM-5 เครื่องจำลองราคา (ดูราคา + margin)

Use case จริง

  1. จำลองราคา → เลือกลูกค้า + สินค้า + จำนวน → เห็นราคาสุทธิ + โปรฯ ที่ได้
  2. เปิดโปร "ลด 20%" → เช็คชนกัน (ซ้อน ≤2) → อนุมัติ → active
  3. โควตา: เซลล์ทำได้ 150K/200K → งบส่วนลดเหลือ 10%
  4. เลือกสินค้าในบิลขาย → SC9 ดึงโปรฯ ที่ match ให้อัตโนมัติ

คำตอบ / กติกาสำคัญ

  • VAT Golden Rule — (ราคาก่อน VAT − ส่วนลด) → +VAT 7% · ห้ามลดจากราคารวม VAT
  • โปรซ้อนได้ ≤ 2 ชั้น — Priority 1-10 · เกิน 2 ชั้นต้องอนุมัติ
  • Rebate ≠ Discount — Rebate = คืนหลังขาย (PO-7) · Discount = ลดก่อนขาย (PM)
  • เตือน margin — GP% <10% เหลือง · <0% แดง ต้อง GM อนุมัติ
  • Sale-In Accrual ย้ายไป PO-7 — จัดซื้อคุม Trade Agreement

Use case จริง

  1. ตั้ง VAT 7% + WHT 3% + GL account → บังคับ posting ถูก
  2. เซลล์อนุมัติ SO <50K · PM อนุมัติ >500K (แยกหน้าที่)
  3. ตั้งค่าแรงช่าง Daikin: senior 800 บาท/ชม → คิด SV invoice
  4. ตั้ง Entity Tag "1" = SWT → FI-13 แยกห้องภาษี

คำตอบ / กติกาสำคัญ

  • ระบบสิทธิ์ = ตำแหน่ง (Position-based RBAC · ADR-0003) — เลิก role ตายตัว 9 อัน → admin สร้าง "ตำแหน่ง" เอง · 1 พนักงาน = 1 ตำแหน่ง · สิทธิ์ CRUD รายหน้า + scope สาขา/แผนก + วงเงิน · สร้างพนักงาน (MD-4) → มอบตำแหน่ง (CF-1) → อนุมัติตามวงเงิน (CF-2.6)
  • CF-2.6 Approval Matrix — routing ตามยอด + SLA + auto-escalate · SL และ PO ต้องผ่านที่นี่ · sync กับ CF-1
  • Maker ≠ Checker — คนสร้าง ≠ คนอนุมัติ (account เดียวห้าม)
  • เลขเอกสาร reset ไม่ได้ — ข้อบังคับภาษี เก็บ 10+ ปี

Use case จริง

  1. Dashboard แสดง "MD-1 sync 2 นาทีที่แล้ว · 9,843 รายการ · OK"
  2. Error "PM-1 HTTP 400" → Admin แก้ข้อมูลใน BC → retry
  3. Webhook: SO posted → ส่ง JSON เข้า Portal → สร้าง GL
  4. Shopee order → sync เป็น SO (P3)

คำตอบ / กติกาสำคัญ

  • Service Account เดียว — ทุก user ผ่าน Portal RBAC → BC 1 license (ประหยัด)
  • Auto-Retry — 5xx retry 3 ครั้ง (5s/15s/60s) · 4xx ไม่ retry · 401 refresh token
  • Rate Limit — BC 600 req/min → Portal batch (10-20/call)
  • ความถี่ sync — MD 15 นาที · SO/PO 5 นาที · GL 30 นาที
