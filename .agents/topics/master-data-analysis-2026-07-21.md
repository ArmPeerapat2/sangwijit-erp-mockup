# วิเคราะห์ระบบเพื่อออกแบบข้อมูลหลัก — 2026-07-21

> Peerapat สั่ง: *"วิเคราะห์ระบบทั้งหมด ว่าการกำหนดสิทธิ์ ขอบเขต การเรียกรายงาน ควรมีฟิลด์ไหนหรือเก็บข้อมูลอะไรประกอบ เพื่อใช้สร้าง master แต่ละส่วน"*

## 🔎 อัปเดต 2026-07-21 (รอบ 2) — เจอเอกสารอ้างอิง ERP เดิมที่ agent ทั้ง 3 ตัวไม่ได้ตรวจ

### 🔑 ค้นพบที่ 1 — ERP เดิมมีโครงสิทธิ์ที่เราต้องการอยู่แล้ว
เมนู `1.5.1 ข้อมูลหลักต่างๆ` ของระบบเดิมมี:
| เมนูเดิม | ตรงกับสิ่งที่เรากำลังออกแบบ |
|---|---|
| **1.5.1.7 กำหนดกลุ่มพนักงาน** | กลุ่มพนักงาน |
| **1.5.1.8 กำหนดตำแหน่งพนักงาน** | **ตำแหน่ง** = ตัวถือสิทธิ์ (ตรงกับ ADR-0003 และที่ Peerapat เคาะว่า "สิทธิ์อยู่ที่ตำแหน่ง") |
| **1.5.1.F กำหนดกลุ่มสิทธิ์พนักงาน** | **กลุ่มสิทธิ์แยกจากตำแหน่ง** — ตรงกับแนวคิด "กลุ่ม = ถังของสิทธิ์" ที่เคาะ 21 ก.ค. |
| **1.5.1.B กำหนดประเภทเงินได้** | ✅ **ตรงเป๊ะกับที่เคาะวันนี้ (Q2)** ว่าอัตราภาษีต้องผูกกับ "ประเภทเงินได้" ไม่ใช่ผูกกับผู้ขาย |
| **1.5.1.C กำหนดประเภทภาษีหัก ณ ที่จ่าย** | ตารางอัตราภาษีกลาง |

→ **สิ่งที่เราเคาะกันมาทั้งวัน ตรงกับที่ ERP เดิมทำอยู่แล้ว** ไม่ใช่การคิดใหม่

## 🚨 3 บล็อกเกอร์ที่ต้องเคาะก่อนออกแบบ (ตรวจเองยืนยันครบ)

### 1. ระบบทำเพื่อ 1 บริษัท หรือ 4 บริษัท — เอกสารขัดกันเอง
| หลักฐาน | บอกว่าอะไร |
|---|---|
| มติ 2026-05-31 (`active.md:440`) | *"Scope = SWT single-entity · **ตัด multi-entity**"* |
| ของที่สร้างจริง | ทะเบียนสาขา **10 สาขา 4 บริษัท** · ศูนย์อนุมัติอ้าง 4 บริษัท **44 จุด** · หน้าสิทธิ์มีคอลัมน์นิติบุคคล |

🔴 **กระทบทุกฟิลด์ของขอบเขตการมองเห็น — ต้องเคาะก่อนข้ออื่นทั้งหมด**

### 2. ทะเบียนพนักงานไม่มีฟิลด์เรื่องสิทธิ์เลยแม้แต่ฟิลด์เดียว
ค้นคำว่า สิทธิ์/permission/ขอบเขต/วงเงิน = **0 ผลลัพธ์** · แต่ **3 หน้าเขียนว่า "สิทธิ์กำหนดที่ทะเบียนพนักงาน"** แล้วชี้มาที่หน้าที่ไม่มีช่องกรอก
**15 สิทธิ์ยังไม่มีที่อยู่** — รวม *ปลดยอดกันสต็อก* (14 จุดใน 3 หน้าปักป้าย "⏸️ รอกำหนดผู้มีสิทธิ์" อยู่จริง)

### 3. ต้นทุนรั่วผ่านหน้าต่างค้นหาสินค้า — **27 ไฟล์**
คอลัมน์ "ต้นทุน INV / ต้นทุน ผปย" โผล่ใน 27 หน้าโดยไม่เช็คสิทธิ์
→ ต่อให้ซ่อนต้นทุนที่หน้าจำลองราคาขายสำเร็จ **พนักงานขายเปิดหน้าต่างค้นหาสินค้าอ่านได้อยู่ดี**

## 🎯 5 ฟิลด์ที่ "ย้อนกลับมาเติมทีหลังไม่ได้" — ต้องตัดสินก่อนเปิดใช้จริง

1. **ต้นทุน ณ วันขาย** ลงบรรทัดใบขาย/ใบงานบริการ — *ต้นทุนถัวเฉลี่ยเคลื่อนที่เปลี่ยนทุกวัน ถ้าไม่ snapshot กำไรเดือนที่แล้วจะเปลี่ยนทุกครั้งที่เปิดรายงาน*
2. **รหัสอาการเสีย / สาเหตุ / วิธีแก้** เป็นรหัสปิด + ช่องบรรยาย — *ตอนนี้เป็นข้อความอิสระ · เป็นข้อมูลมีค่าที่สุดของธุรกิจที่มีศูนย์ซ่อม*
3. **เป้ารายงวด** (คน · ทีม · สาขา · หมวด) — *มีคอลัมน์ "เป้า" รออยู่ 2 หน้า แต่ไม่มีที่เก็บเลย*
4. **ราคาปกติก่อนลด + รหัสโปรฯ + แหล่งงบส่วนลด** ที่บรรทัดใบขาย — *แยกไม่ออกว่าโปรฯ กินกำไรหรือเซลกินกำไร · ถ้าแบรนด์ออกงบ กำไรบริษัทไม่ได้ลดจริง*
5. **ธงช่างใน/ช่างนอก + รหัสประเภทงานบริการ** ในทะเบียนพนักงาน — *4 หน้าลิงก์ `TECH-007` เข้ามาแล้วแต่ไม่มีฟิลด์รองรับ*

**เติมทีหลังได้ ไม่ต้องรีบ:** ธงคลังขายได้/ไม่ได้ · SLA เคลมผู้ขาย · ประเภทธุรกิจลูกค้า · ค่าใช้จ่ายสาขา · พิกัดแผนที่

| **พนักงาน** | 🔴 **ผิดโจทย์** | เป็นเทมเพลต HR สากล (อังกฤษล้วน + วันลา + performance + payroll) · **ทุกสิ่งที่ระบบต้องการไม่มีสักอย่าง** · แถมมี modal ค้นหาสินค้าฝังผิดที่ |

### ลำดับ grill ที่แนะนำ
1. **ทะเบียนพนักงาน** — ของค้างเยอะสุด · **4 โมดูลหยุดรออยู่** (ขาย/คลัง/บริการ/การเงิน)
2. **ทะเบียนผู้ขาย** — เป็นปลายทางของ "ช่างนอก = เจ้าหนี้ปกติ" ที่เคาะ 21 ก.ค. → grill คู่กับตัวที่ 1
3. **ทะเบียนสาขา & คลัง** — ต้องเคาะธงขายได้/ไม่ได้ + เจ้าของเลขรันเอกสาร + รหัสคลังมาตรฐาน **ก่อนที่ทะเบียนสินค้าจะผูกคลังได้**
4. **ทะเบียนสินค้า** — grill เชิง "ตัดของไม่ใช้ + ชี้ขาดโมเดลราคา/ต้นทุน" ไม่ใช่เพิ่มฟิลด์
5. **ทะเบียนลูกค้า** — เกือบพร้อม เก็บตกทีหลังได้

## ❓ คำถามรอ Peerapat เคาะ (รวมจาก 3 มุม)

**กลุ่ม A — ต้องเคาะก่อนเริ่มออกแบบ**
- A1 · **1 บริษัท หรือ 4 บริษัท** (บล็อกทุกอย่าง)
- A2 · **เก็บต้นทุน ณ วันขายลงบรรทัดใบขายไหม** — แนะนำ *เก็บ (snapshot)*
- A3 · **อาการเสียเป็นรหัสหรือข้อความ** — แนะนำ *รหัสปิด + ช่องบรรยาย* (แบบเดียวกับผังเหตุผลปรับสต็อกที่เคาะแล้ว)

**กลุ่ม B — โครงสร้างข้อมูลหลัก**
- B1 · **1 คนได้กี่ตำแหน่ง** — แนะนำ *1 ตำแหน่ง + ช่อง override รายคน*
- B2 · **ทะเบียนพนักงาน แยก HR ออกจากทะเบียนใช้งานไหม** — แนะนำ *ที่เดียวแต่ซ่อนด้วยสิทธิ์รายแท็บ* (ลอกแบบทะเบียนลูกค้าที่ทำแล้ว)
- B3 · **"เป้า" เก็บที่ไหน** — แนะนำ *BC Budget* รอง *ทะเบียนเป้าแยก* · **ห้ามเก็บเป็นฟิลด์ในทะเบียน** (ทับของเดิม ปีก่อนหายถาวร)
- B4 · **"ช่องทาง" เป็นมิติของอะไร** — แนะนำ *ของสาขา + ค่าตั้งต้นจากสาขา* (เพราะ HQ ขายทั้งปลีกและส่ง)
- B5 · **"หมวดรายได้" แยกที่สินค้าหรือบรรทัดเอกสาร** — แนะนำ *ที่ทะเบียนสินค้า* โดยขยายค่าของ `Income Type`/`SKU Type` ที่มีอยู่แล้ว

**กลุ่ม C — นโยบายองค์กร**
- C1 · **ใครเห็นต้นทุนได้** — แนะนำ *ซ่อนตัวเลข โชว์สัญญาณไฟเขียว/เหลือง/แดง* · ⚠️ ต้องอุดรู 27 ไฟล์ก่อน
- C2 · **ใครเห็นเงินเดือน** — แนะนำ *แยกสิทธิ์แท็บค่าตอบแทน* · ❌ **ห้ามปล่อยไว้เฉย ๆ เด็ดขาด** (ตอนนี้ใครเปิดทะเบียนพนักงานได้ = เห็นเงินเดือนทุกคน)
- C3 · **เห็นเอกสารข้ามสาขาได้แค่ไหน** — แนะนำ *พนักงานเห็นของตัวเอง · ผจก.สาขาเห็นทั้งสาขา · ผู้บริหารเห็นหมด*
- C4 · **ใครได้สิทธิ์ปลดยอดกันสต็อก** (ค้างจาก 20 ก.ค.) — แนะนำ *เป็นธงตั้งค่าได้ + ค่าตั้งต้น = เซลเจ้าของใบปลดใบตัวเองได้*

## ⚠️ ข้อจำกัดของการวิเคราะห์นี้
- ทั้ง 3 agent อ่านไฟล์ใหญ่แบบ**สกัดชื่อฟิลด์/หัวตาราง** ไม่ได้อ่านทุกบรรทัด — อาจมีฟิลด์ซ่อนใน JS หรือ modal ที่ยังไม่ render
- **ไม่ได้ตรวจ `sangwijit-bc-mockup/` · `knowledge-base/` · `docs/` · `Flow Design/`** — อาจมีสเปกฟิลด์ฝั่ง BC ที่ครอบช่องว่างบางข้อไว้แล้ว **ควรตรวจก่อนเคาะจริง**
- รายการ "ฟิลด์ที่ไม่มีใครใช้" พิสูจน์ด้วยการค้นคำกลับ = หลักฐานระดับ *"ไม่พบผู้ใช้"* ไม่ใช่ *"ยืนยันว่าไม่มีผู้ใช้แน่นอน"*
- ยังไม่มีใครเห็นหน้าจอ render จริงทั้งเซสชัน (ระบบบล็อก `file://`)
