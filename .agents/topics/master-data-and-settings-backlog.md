# ข้อมูลหลัก + ตั้งค่าระบบ — รายการที่สะสมจากการ grill

---

## 🚨 บล็อกเกอร์ที่ต้องเคาะก่อนออกแบบข้อมูลหลัก (พบ 2026-07-21)

### 1. ✅ RESOLVED (grill 2026-07-24) — ระบบทำเพื่อ **1 บริษัท (SWT)** · 4 = สาขา
- **Q1 เคาะ:** ยืนมติ 05-31 → 1 บริษัท (SWT single-entity) · 4 ตัว (วีมันนี่/วินมันนี่/รีพาวเวอร์/สนง.ใหญ่) = **สาขา** ไม่ใช่ 4 นิติแยก
- **Q2 เคาะ:** ฟิลด์ "นิติบุคคล" ที่หลุด → เปลี่ยนเป็น **"สาขา" + ใช้มิติ SITECODE** (reuse 5 มิติเอกสาร 07-23) แยกดูรายงานต่อขาธุรกิจ
- **ตรวจ implementation:** แก้ไปแล้ว ~90% — md5 สาขา + cf1 สิทธิ์ cleaned 07-21 (ถอด `.entity-*`) · "นิติบุคคล" ในหน้าภาษี = ภ.ง.ด.53 (ถูกต้อง เก็บ) · SWE1/SWEPO/SWE-HaierShop = รหัสสาขา/เลขเอกสาร legit · ex1 section นิติ + Entity Tag เอกสารขาย = tracked P2 (C6=ข · FI-13/CF-2.8 defer) — ไม่มีงาน build ค้างที่ไม่ tracked
- _(เดิม: มติ 05-31 vs ของสร้าง 4 บริษัท ขัดกัน → เคาะแล้วว่ายืน 1 บริษัท)_

### 2. ✅ RESOLVED (grill + build 2026-07-24) — md4 มีแท็บสิทธิ์แล้ว (สืบจากกลุ่ม · read-only)
- **Q1 เคาะ:** สิทธิ์ผ่าน **กลุ่ม/ตำแหน่ง** พอ · **ไม่มี override รายคน** (ต้องการต่าง = สร้างกลุ่มใหม่)
- **Q2 เคาะ:** md4 เลือกตำแหน่ง+กลุ่ม → โชว์สิทธิ์ **read-only** · แก้จริงที่ CF-1 (permission-matrix 155 checkbox = แหล่งจริง)
- **build:** `md4` แท็บ "🔑 สิทธิ์การใช้งาน" — MD-4.6 มอบหมายกลุ่ม + MD-4.7 ตารางสิทธิ์ 14 สิทธิ์ 4 หมวด (อนุมัติ/คลัง/ขาย-ราคา/ขอบเขต) รวมจากหลายกลุ่ม (union) ✓ verified render+logic · console clean
- **relabel:** 16 จุด (ap1/sl2/wh-q2/wh2r) "กำหนดที่ทะเบียนพนักงาน"→"กำหนดที่กลุ่มสิทธิ์"
- _(เดิม: md4 = 0 ฟิลด์สิทธิ์ · 15 สิทธิ์ไม่มีที่อยู่ · 6 หน้าชี้หน้าไม่มีช่อง → เคาะ+ทำแล้ว)_
- ⏳ ค้างเสริม (P2/ตอนตั้งค่าจริง): cf1 group-level tick + drill-down (07-21) · ทะเบียนตำแหน่ง/กลุ่มสิทธิ์ เป็น master จริง · ธงช่างใน/นอก

### 3. ✅ RESOLVED (grill + build 2026-07-24) — gate ต้นทุนที่ sc2 (shared · แก้จุดเดียวอุดทุกหน้า)
- **Q1 เคาะ:** ไม่มีสิทธิ์ → **ซ่อนคอลัมน์หาย** (ไม่ render ค่าลง DOM · ไม่ใช่ blur/***)
- **Q2 เคาะ:** ต้นทุน 2 ตัว (INV/ผปย) **คุมรวม 1 สิทธิ์ view-cost** (ที่ใส่ใน md4/cf1 matrix แล้ว)
- **Q3 เคาะ:** อุด **sc2 ค้นหาสินค้า ก่อน** (รูรั่วให้พนักงานขาย) · หน้าการเงิน/ผู้บริหาร (rp1/cm1/fi4/ex1/md1) ใช้ view-cost เดียวกัน คนกลุ่มนั้นมีสิทธิ์อยู่แล้ว → ยังไม่ต้องไล่
- **build:** `sc2-item-search` — ค่าต้นทุนย้ายออกจาก HTML ไปเก็บ JS · toggle จำลองสิทธิ์ · `scRenderCost()` inject เฉพาะมีสิทธิ์ · verified: ปิด→ค่าไม่อยู่ใน table cell ใดๆ · console clean
- ⚠️ mockup caveat: ค่ายังอยู่ใน `<script>` literal (real app: server ส่งเฉพาะคนมีสิทธิ์ = 0 leak) — comment ในโค้ดระบุ
- ⏳ ค้างเสริม (ตอนต่อ API จริง): ผูก scRenderCost กับ session สิทธิ์จริง · ไล่ gate rp1/cm1/fi4/ex1/md1 ถ้าต้องการเข้ม (ปัจจุบัน role-appropriate)

> **เอกสารนี้โตขึ้นเรื่อย ๆ** — ทุกครั้งที่ grill โมดูลใหม่แล้วเจอว่า "ต้องมีข้อมูลหลักตัวนี้" หรือ "ต้องตั้งค่านี้ได้" ให้มาเติมที่นี่
> **ยังไม่ต้องตัดสินใจอะไร** — เก็บไว้ก่อน แล้วค่อยเอาไปใช้ตอน grill ข้อมูลหลักและตั้งค่าระบบจริง
> วิธีใช้: ตอนจะ grill ข้อมูลหลัก → เปิดไฟล์นี้ จะเห็นว่ามีอะไรค้างรออยู่บ้าง ไม่ต้องมานั่งนึกใหม่

## 🔑 หลักการที่ต้องยึดตอน grill ข้อมูลหลัก/ตั้งค่าระบบ

**ลายเซ็นการตัดสินใจของ Peerapat (เห็นซ้ำ 5 ครั้งแล้ว):**
> *"ถ้ากลไกมาตรฐานครอบได้ อย่าสร้างกฎใหม่"*

ปรากฏที่: สิทธิ์ (ใช้ RBAC) · การอนุมัติ (ใช้ศูนย์อนุมัติกลาง) · คลังพิเศษ (ใช้กลไกคลังเดิม) · ตัดหน้ารับของฝั่งบัญชี (ใช้สิทธิ์แทนสร้างหน้า) · โปรฯ ชนกัน (ใช้กลไกหน้าจำลองราคาเดิม)

→ **เวลาเสนอทางเลือกเรื่องข้อมูลหลัก/ตั้งค่า ให้เช็คก่อนเสมอว่ามีของเดิมครอบได้ไหม** ถ้ามี ให้เสนอข้อนั้นเป็นข้อแนะนำ

**อีกข้อที่เห็นชัด:** ชอบ **"ตั้งค่าเองได้"** มากกว่าค่าตายตัว (ยอดกันสต็อก · วันเตือนซาก) — แต่ไม่ใช่ทุกเรื่อง (ส่วนต่างการนับ = ไม่มีข้อยกเว้นเด็ดขาด)
→ เวลาเสนอ ให้ถามว่า **"ตัวนี้ควรตั้งได้ หรือควรตายตัว"** อย่าเดาเอง
