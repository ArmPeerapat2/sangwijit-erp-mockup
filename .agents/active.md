## 📦 WH Audit + grill (2026-07-20 · กำลังดำเนินการ)

**ปิด 2 เรื่องจาก audit จัดซื้อ:** (1) **GRN = คลังหน้าเดียว (WH-1)** จัดซื้อห้ามสร้าง/แก้/ผลิตเลข GRN · PO-5 ถ้า build = read-only 3-way match view (2) **PO-8 บิลฝากห้ามผลิตแถว movement** — ของเข้าใช้ GRN + ธง consignment · Stock Card กรองด้วย whitelist ประเภทธุรกรรม

**decisions (Peerapat):**
- **in-transit = มีคลังพักจริง (ก)** — ของย้าย location `IN-TRANSIT` ผูกใบโอน · ปลายทางรับ = ย้ายเข้าคลังปลายทาง · **ยอดรวมบริษัทบรรจบทุกวัน** · WH-R ต้องมียอด in-transit แยก · chip คิวรับอ่านจากยอดเดียวกัน
- **consignment = นับเป็นสต็อก + ธง ownership=vendor แต่อยู่คลังแยก (ข+)** — ใช้กลไกเดียวกับคลังพัก: **location `CONSIGNMENT` (คลังฝาก)** แยกจากคลังขายปกติ · เห็นของ/นับ/track serial ได้ แต่ไม่ปนสต็อกพร้อมขาย · ซื้อขาด = ย้าย คลังฝาก→คลังปกติ (1 movement · ownership เปลี่ยน) · งบ/MOS กรองด้วย location+ธง
- **costing = Moving Average เป็นทางการ (ก)** · FIFO layer ที่ WH-R = **ข้อมูลประกอบดูอายุ lot เท่านั้น ไม่ใช่ตัวเลขบัญชี** → WH-5/WH-R/WH-NM ดึง `unitCost` จาก BC ตัวเดียว **ห้ามคูณ/เฉลี่ยเอง** · ตัวเลขก่อน post ติดป้าย "ประมาณการ" ทุกที่ · FIFO layer เชื่อมรายงานสินค้าไม่เคลื่อนไหวได้
- **สิทธิ์ปรับสต็อก = RBAC มาตรฐาน ไม่มีกฎพิเศษ** — พนักงาน→ตำแหน่ง→เข้าเมนูได้ = แก้สต็อกได้ (CF-1) · **ไม่มีวงเงินแยกต่อใบ** · ยังผ่านศูนย์อนุมัติกลาง Maker≠Checker ตามที่ build ไว้แล้ว
- **อนุมัติทุกกรณี (คำขอโอน · ตัดจำหน่ายเครื่องตกค้าง · ปลดยอดกัน) = RBAC + ศูนย์อนุมัติกลาง เหมือนกันหมด** ไม่มีกฎเฉพาะรายเรื่อง
- 🔒 **ศูนย์อนุมัติกลาง (AP-1) ต้อง scope ตามสิทธิ์รายคน** — กำหนดตอน**สร้างพนักงาน**ว่า (ก) เข้าศูนย์อนุมัติได้ไหม (ข) อนุมัติ**ข้อมูลด้านใด**ได้บ้าง → ผู้อนุมัติเห็นเฉพาะเรื่องในขอบเขตตัวเอง ไม่ใช่ทุกคนเห็นทุกใบ · **เป็น requirement ของ AP-1 + ทะเบียนพนักงาน (MD-4/CF-1)**

- **ของค้างรับตอน short-close = ยกเลิกทิ้ง (7.3-ต่อ ก)** — ตัดออกจากใบสั่งซื้อเลย ไม่ตั้งค้างส่งรอบหน้า · ต้องการของเพิ่ม = เปิดใบสั่งซื้อใหม่ (ยอดค้างส่งสะสมทำให้ตัวเลขจัดซื้อเพี้ยน)

    - ✅ ตารางมอบอำนาจชั่วคราว (คนลา→มอบคนอื่น) **คงไว้** — เป็นรายการธุรกรรม ไม่ใช่ config ผูกตำแหน่ง

### 💰 FI Audit + grill (2026-07-21)
**audit:** 1 agent อ่านครบ 9 หน้า · **ผมตรวจซ้ำข้ออ้างหลัก 6 ข้อเอง ผ่านหมด** (อัตราภาษีขัดกันจริง · `swtCalcBillSummary` ไม่ถูกเรียกเลยสักหน้า · ลิงก์ตาย 2 จุดจริง · ศูนย์อนุมัติไม่มีประเภทจ่ายเงิน · ช่องโหว่ ก/ข/ค = 0 ผลลัพธ์จริง)
**สภาพโมดูล:** "หน้าจอครบ แต่กติกาไม่ตรงกัน" — 5 เรื่องอันตราย (อัตราภาษีขัดกัน 2 หน้า · ฐานคำนวณคิดจากยอดรวม VAT · ใบจ่ายเงินไม่มีที่ยืนในศูนย์อนุมัติ · หน้าใบสำคัญค่าใช้จ่ายขัดแย้งกับตัวเอง · คิวติดป้ายผิด 3 จุด)

**🔒 เคาะแล้ว 6 ข้อ:**
- **Q1 ฐานคำนวณภาษีหัก ณ ที่จ่าย = ฐานก่อน VAT (ก) · แต่แก้เองได้** — ระบบคำนวณให้เป็นค่าตั้งต้นจากฐานก่อน VAT · ผู้ใช้กรอกทับได้กรณีพิเศษ (ไม่ล็อกตาย) → ปิดบั๊กที่หน้าจ่ายเงินคิดจากยอดรวม VAT (ต่าง 1,135 บาท/ใบ)
- **Q2 ตารางอัตราภาษี = ตารางกลางผูกกับ "ประเภทเงินได้" (ข)** — ไม่ผูกกับผู้ขาย เพราะผู้ขายรายเดียวจ่ายได้หลายประเภท (Daikin: ค่าสินค้า 0% · ค่าติดตั้ง 3%) · หน้าจ่ายเงิน+ใบสำคัญค่าใช้จ่าย **อ่านอย่างเดียว ห้ามพิมพ์อัตราเอง**
- **Q3 ลูกหนี้พนักงาน = เพิ่มประเภทลูกหนี้ "พนักงาน" ในหน้ารับชำระ (ก)** — เลือกคู่สัญญาจากทะเบียนพนักงานได้ · ยอดค้างเห็นในคิวเหมือนลูกหนี้ทั่วไป (accountability ถึงตัวบุคคล ตาม 7.4)
- **Q4 ตั้งหนี้ช่างนอก = เพิ่มโหมด "ตั้งหนี้ไม่อ้างใบสั่งซื้อ" ในหน้าใบตั้งหนี้เดิม (ก)** · 🆕 **ช่าง = เจ้าหนี้การค้าธรรมดา** (อยู่ในทะเบียนผู้ขาย ไม่ใช่ประเภทพิเศษ) **ทำจ่ายค่าแรงตามสายจ่ายปกติ** — ไม่ต้องสร้าง flow แยก
- **Q5 หน้าใบสำคัญค่าใช้จ่าย = บันทึกค่าใช้จ่ายอย่างเดียว (ก)** — ตัดปุ่มนำส่งสรรพากร + การ์ด KPI เรื่องภาษีออก · **ต้องพ่วงเพิ่มช่อง VAT/ภาษีซื้อ** ไม่งั้นภาษีซื้อจากค่าเช่า/ค่าบริการหายจากรายงาน
- 🔴 **หลักการสำคัญ: ห้ามฟิกตำแหน่งผู้อนุมัติลงใน mockup (Peerapat 2026-07-21)**
  - *"คนอนุมัติจริงจะอยู่ที่ตำแหน่ง เราไม่ฟิกตำแหน่ง อยู่ที่การตั้งค่าของ user, ตำแหน่ง"*
  - → **ห้ามเขียนว่า "ผู้จัดการคลังอนุมัติเรื่องสต็อก"** หรือผูกกลุ่มเข้ากับตำแหน่งใด ๆ ในหน้าจอ
  - → **กลุ่ม = ถังของสิทธิ์** (unit of permission) · **ใครได้ถังไหน = ค่าตั้งค่าที่ทะเบียนพนักงาน/ตำแหน่ง** เปลี่ยนได้ตลอดโดยไม่ต้องแก้โปรแกรม
  - ⚠️ **ผมเกือบพลาด** — ตารางที่เสนอไปมีคอลัมน์ "คนอนุมัติจริงคือใคร" ระบุตำแหน่งตายตัว · Peerapat แก้ให้ · **เอาคอลัมน์นั้นออก**
- 🆕 **Q9 ค่าเช่า/VAT = ทำเป็นช่องเลือกได้รายบรรทัดว่ามี VAT หรือไม่ (ค)** — รองรับทั้งเช่าอสังหาฯ (ยกเว้น VAT ตามกฎหมาย) และเช่ารถ/อุปกรณ์ (มี VAT) ซึ่งเกิดจริงทั้งคู่
- 🆕 **Q10 อัตรา 15% = ไม่มีเคส** — ยืนยันว่าไม่ต้องมีในตารางอัตรา (ที่ agent ตัดออกไปแล้วถูกต้อง)
- 🆕 **Q11 ใบจ่ายเงิน = 1 ใบ ต่อ 1 เจ้าหนี้ · แต่รวมได้หลายรายการ/หลายใบตั้งหนี้ของเจ้าหนี้รายนั้น** — 🔧 ต้องแก้กลับ เพราะ agent ทำเป็นชุดจ่ายหลายเจ้าหนี้ไว้
- 🆕 **Q8 ศูนย์อนุมัติกลาง = ต้องจัดกลุ่มประเภทเอกสาร + ใส่เหตุผลกำกับ (Peerapat สั่ง 2026-07-21)**
  - **เหตุผลที่สั่ง:** *"เวลาอนุมัติแต่ละส่วน อาจจะกำหนดสิทธิ์ให้เห็นตามกรุ๊ปได้อีกทีนึง"* → **กลุ่ม = หน่วยของการให้สิทธิ์** ไม่ใช่แค่จัดหน้าจอให้สวย
  - แต่ละประเภทเอกสารต้องมี **คำอธิบายว่าอนุมัติเรื่องนี้คืออนุมัติอะไร มีผลอะไรตามมา** — คนอนุมัติจะได้รู้ว่ากำลังเซ็นอะไรอยู่
  - **🔗 ผูกกับ [[master-data-and-settings-backlog]]:** ตอนกำหนดสิทธิ์ที่ทะเบียนพนักงาน/ตำแหน่ง ต้องให้สิทธิ์**ระดับกลุ่ม**ได้ (ไม่ใช่ติ๊กทีละประเภท) และซอยลึกถึงรายประเภทได้ถ้าต้องการ
  - ✅ **ทำแล้ว 2026-07-21** — `ap1-approval-center-mockup.html` จัดกลุ่มทั้งตัวกรองแท็บรออนุมัติและแท็บประวัติ (`<optgroup>`) + การ์ดอธิบาย 4 กลุ่มพร้อมบอกว่า**เซ็นแต่ละเรื่องแล้วเกิดอะไร**

    - **🛒 จัดซื้อ** = ใบสั่งซื้อ → ผูกพันกับผู้ขาย แต่**ยังไม่เกิดเงินออก**
    - **🏷️ ราคา/ส่วนลด** = ขอราคาพิเศษ · ใบลดหนี้ · บิลขาย · **โปรฯ ต่ำกว่าทุน** → เงินไม่ออก แต่รายได้หาย
    - **📦 สต็อก** = ปรับ/ตัดสต็อก · โอนสินค้า · ตัดจำหน่ายเครื่องลูกค้า → ตัวเลขคงคลัง+มูลค่าสินทรัพย์เปลี่ยน
  - **ใส่คำเตือน dev ในหน้าจอ: "ห้าม hardcode ตำแหน่งผู้อนุมัติ"** — โครงสร้างองค์กรเปลี่ยนได้
- **Q7 ผังบัญชี = ตั้งที่ BC อย่างเดียว · พอร์ทัลดึงมาแสดงให้เลือก (ก)** — พอร์ทัล**ไม่มีหน้าผังบัญชี** · ทุกที่ที่ต้องเลือกบัญชี (ผังเหตุผลปรับสต็อก · ตัดจำหน่ายเครื่องลูกค้า · ลูกหนี้พนักงาน) = dropdown ที่ดึงจาก BC · ตรงกับกฎเดิม "การลงบัญชี BC เป็นเจ้าของ ห้ามแยก" (CF-2.3)
