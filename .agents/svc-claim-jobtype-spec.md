## 0. แยก 2 concept ก่อน (สำคัญสุด — อย่ารวมกัน)

| | ① เคลมสินค้า (Product Claim) | ② เคลมงานบริการ (Service Warranty Claim) |
|---|---|---|
| คืออะไร | ของที่**เราซื้อมา**เสีย → ส่งคืนบริษัท (vendor) ทั้งชิ้น | เราเป็น**ศูนย์บริการ** ซ่อมของในประกัน **ไม่ว่าลูกค้าซื้อจากไหน** |
| ของอยู่ไหน | **หายจากสต็อกเรา** (ส่งคืน vendor รอผลลัพธ์) | **อยู่กับลูกค้า** เราแค่ซ่อม/เปลี่ยนอะไหล่ |
| เงื่อนไข | ต้อง**ซื้อกับเรา** — อ้างบิลซื้อของเรา (จาก S/N) | ตรวจ S/N กับ**แบรนด์** ว่าในประกันไหม |
| ผลลัพธ์ | S1-S4 (ดู §5) — ส่วนมากได้ **ส่วนลด (CN)** | ซ่อม/เปลี่ยนอะไหล่ + เก็บรายได้ 3 อย่าง (ดู §4) |
| chain | **CLM → PO-CN** (ฝั่ง vendor/AP) | SV-1 → SV-5 → SV-4 → SV-7 (ฝั่งบริการ) |

> **"งานเบิกค่าแรง/งานบริการ ≠ งานเคลมสินค้า"** — คนละ flow คนละ ledger

### sub-type เคลม (จาก wip Design Note · reconcile 2026-07-02) map เข้า 2 concept
| sub-type เดิม | = ในโมเดลนี้ |
|---|---|
| **Warranty** | ② เคลมงานบริการ (ของอยู่กับลูกค้า · ในประกัน) |
| **Pre-sale** | ① เคลมสินค้า (ของยังเป็นสต๊อกเรา ก่อนขาย · **ไม่มีลูกค้า** — ดู §12.2) |
| **Goodwill** | ไม่ใช่ sub-type — เป็น **payer option** (การตัดสินใจคนจ่าย · ดู §12.1) |

- งานเคลม (CL-1 เดิม) **ไม่เป็น module แยก** — เป็น **job type ใน SV-1 Service Intake**

- **claim = job type ไม่ใช่ source** — source (walk-in/โทร/LINE/แบรนด์ส่งมา) = ช่องทางล้วน ไม่กำหนดชนิดงาน

### 5 Job Types
| Job type | extension | รายได้ | หมายเหตุ |
|---|---|---|---|
| 🔧 ซ่อม | core | ค่าแรง/อะไหล่/เดินทาง | งาน default |
| ♻️ เคลม (②) | popup (built) | ตาม §4 | เคลมงานบริการในประกัน |

## 2. Entry — Resolution Menu A-E (S/N-first) [grill 2.1]

สแกน/กรอก Serial ก่อน → ระบบ resolve 5 ทาง:

| เมนู | เงื่อนไข | ไปทางไหน |
|---|---|---|

| **B** | เจอ S/N + **หมดประกัน** | งานซ่อมปกติ คิดเงินลูกค้า (ไม่ใช่ job type เคลม) |

## 3. ประกัน = per-component (สำคัญ) [grill 2.3]

- **ประกันผูกกับ component + อายุของมันเอง** ไม่ใช่ธง in/out รายเครื่อง
  - ตัวอย่างแอร์: เครื่อง 1 ปี · คอมเพรสเซอร์ 5 ปี
- ตรวจ S/N → ต้องได้**ตารางประกันรายชิ้น** (component × วันหมดประกัน)
- ในงานเดียวเสียหลายชิ้น → บางชิ้นในประกัน บางชิ้นหมด (เช่นปี 2-5: บอร์ดหมด · คอมเพรสเซอร์ยัง)

## 4. รายได้งานบริการ ② — 3 อย่าง (ค่าแรง/อะไหล่/เดินทาง) [grill 2.3]

**คนจ่ายขึ้นกับสถานะประกันรายรายการ ไม่ใช่ช่องทางรับงาน** (ลูกค้าซื้อที่อื่นแต่ในประกันแบรนด์ = แบรนด์จ่าย)

### Billing = assignable payer ต่อบรรทัด (ที่ SV-4 pricing)
- ทุกบรรทัดรายได้ (ค่าแรง/อะไหล่/เดินทาง) มี dropdown **"คนจ่าย: แบรนด์ / ลูกค้า"**
- **default อัตโนมัติ** จากตารางประกันรายชิ้น (ค่าอะไหล่ประเมินรายชิ้น: บอร์ดหมด→ลูกค้า · คอมเพรสเซอร์ยัง→แบรนด์)
- **ค่าแรง default:** มีรายการนอกประกันแม้ชิ้นเดียว → ลูกค้าจ่าย · ทุกชิ้นในประกัน → แบรนด์จ่าย — **แต่ admin แยกเป็น 2 บรรทัดได้** ถ้าแบรนด์จ่ายค่าแรงบางชิ้นแยก
- **ค่าเดินทาง:** ตัวแปรแยก ขึ้นกับนโยบายแบรนด์ (ในประกันก็อาจไม่ให้) → ไม่มี default อัตโนมัติ ให้ admin เลือก
- **admin override ได้ทุกบรรทัด** (SV-4 = admin pricing อยู่แล้ว — คนรู้เงื่อนไขแบรนด์จริงตัดสิน)

### ปลายทางเอกสาร
- บรรทัด "แบรนด์" → รวมเป็น **ARI** (Vendor billing AR · มีใน clm-vendor-claim mockup แล้ว)
- บรรทัด "ลูกค้า" → รวมเป็น **SL-4** บิลขาย
- **งานเดียวออกได้ 2 บิล** (ARI + SL-4) กรณีผสม

## 6. อะไหล่ 2 แหล่ง + Return Flow (pain point) [grill 2.2 / 2.5]

| แหล่งอะไหล่ | ได้มายังไง | ซ่อมเสร็จคืนไหม |
|---|---|---|
| **ในประกัน (เคลม)** | แบรนด์ส่งฟรี | ✅ **ต้องคืนของเก่าให้ vendor** (gate) |
| **นอกประกัน** | **ทำใบสั่งซื้อ PO** (vendor/ร้านนอก) via **SV-Order** | ❌ **ไม่ต้องคืน** (ซื้อขาด) |

### Track 3 ขา
- 🛒 **การสั่งอะไหล่** — PO/SV-Order (นอกประกัน) · แบรนด์ส่ง (ในประกัน)
- 📤 **การเบิกอะไหล่** — SV-3 (จากสต็อก)
- ↩️ **การคืน** — เฉพาะอะไหล่ในประกัน

### Return obligation (เฉพาะในประกัน) — per-line pairing
- **1 งานมีหลายอะไหล่** — จับคู่เป็นราย **line อะไหล่** (ผูก part + S/N เครื่อง) แต่ละชิ้นวงจร รับ→เปลี่ยน→คืน ของตัวเอง
- **3 สถานะต่อ line:** ⬇️ รับจากแบรนด์ (รอส่ง/รับแล้ว+tracking) · 🔧 เปลี่ยน (บันทึก SV-5) · ⬆️ คืนของเก่า (รอคืน/ส่งแล้ว+tracking/แบรนด์รับแล้ว)
- **🔒 Gate ปิดงาน:** ค้างคืนอะไหล่แม้ line เดียว → SV-4/SV-7 badge "⛔ ค้างคืนอะไหล่ x ชิ้น" ปิดงานไม่ได้ (หลักเดียวกับ gate ของก่อนเงิน)
- **Aging alert:** อะไหล่เก่าค้างคืนเกิน X วัน → เตือน (แบรนด์มี deadline คืน ไม่งั้นโดนคิดเงินอะไหล่)
- **Exception ไม่ต้องคืน:** flag ต่อ line — **แบรนด์ยืนยันก่อน → admin ติ๊ก** (ช่างติ๊กไม่ได้) + ระบุเหตุผล · **default = ต้องคืน**

## 12. เพิ่มจาก reconcile wip + grill รอบ 2 (2026-07-02)

### 12.1 Goodwill = payer option ที่ 3 (ต่อยอด §4 billing)
- ปกติคนจ่าย: ในประกัน→แบรนด์ · หมดประกัน→ลูกค้า
- **Goodwill = หมดประกัน/ไม่เข้าเงื่อนไข แต่มีคนรับภาระให้** — 2 แบบ: **แบรนด์-goodwill** / **SWT-goodwill** · ลูกค้าไม่จ่าย
- เป็น dropdown "คนจ่าย" ตัวเลือกเพิ่มที่ SV-4 (ไม่ใช่ sub-type/เอกสารใหม่)
- **ต้องอนุมัติตาม tier + บันทึกเหตุผล** (เพราะยกเงินให้ = เสี่ยง fraud/relations decision)

### 12.2 Pre-sale = ① เคลมสินค้า (ไม่มีลูกค้า)
- ของเสียตอน**ยังเป็นสต๊อกเรา ก่อนขาย** — เจอตอน incoming QC / pre-delivery check / DOA แกะกล่อง
- **ไม่มีลูกค้าเข้ามาเกี่ยว** — อ้างอิง**การรับเข้า/บิลซื้อของเราเอง** → ส่งคืน vendor ได้เลย (CLM→PO-CN · S1-S4)

### 12.3 Refund ≤ sale price (cap บน SL-CN)
- **คืน/ลดหนี้ต่อบรรทัด ≤ ราคาขายเดิม**ในบิลต้นทาง (SL-CN บังคับอ้างบิลอยู่แล้ว → เทียบรายบรรทัดได้)

### 13.1a ✅ Stage 7 "เปิดบิลเครดิต → ลูกหนี้อัตโนมัติ" — verified BC standard (Microsoft Learn · 2026-07-12)
- **ตั้งแบรนด์เป็น Customer** (นอกจากเป็น Vendor) → Post บิล ARI แบบเครดิต (Payment Terms) → BC สร้าง **Customer Ledger Entry (ลูกหนี้เปิด) อัตโนมัติ** — พฤติกรรมมาตรฐาน ไม่ต้อง custom
- **หักกลบลูกหนี้↔เจ้าหนี้ (netting) = BC standard เช่นกัน**: "Consolidate Balances for a Company that is a Customer and a Vendor"
  1. ผูก Customer + Vendor ของแบรนด์เดียวกันผ่าน **Contact type Company** (1 contact ต่อราย)
  2. Customer Card จะมี field **"Balance as Vendor"** · Vendor Card มี **"Balance as Customer"**
  3. Payment Journal → action **"Net Customer/Vendor Balances"** → สร้าง journal lines หักกลบ (ยังไม่ post — คนตรวจก่อน ตรง Maker≠Checker)
  - prereq: Marketing Setup → ใส่ business relation codes (Customers/Vendors)
  - ต่างสกุลเงิน → แยกบรรทัดต่อสกุล
  - ref: learn.microsoft.com/dynamics365/business-central/finance-consolidate-customer-vendor-balances
- **งาน BC dev**: setup แบรนด์เป็นคู่ Customer+Vendor + contact link ตอน onboard (md3) · portal แค่แสดง "Balance as Vendor/Customer" บนหน้าแบรนด์
