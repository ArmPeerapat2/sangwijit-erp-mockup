# การนับสต็อก (Stock Count / Physical Inventory)

---

## ทำไมต้องนับสต็อก

```
ระบบอาจผิดพลาดได้จาก:
  → บันทึกรับ/จ่ายผิดพลาด
  → สินค้าถูกหยิบโดยไม่บันทึก
  → สินค้าหายหรือเสียหายโดยไม่รู้
  → S/N สลับกัน

การนับสต็อกสม่ำเสมอ = รู้ความจริงเร็ว = แก้ไขได้ทัน
```

---

## ประเภทการนับสต็อก

### 1. นับรายวัน (Daily Quick Count)
```
ใครนับ: พนักงานคลังประจำ
นับอะไร: สินค้าที่มีการเคลื่อนไหวในวันนั้น
          (รับเข้า + จ่ายออก)
วิธี: ตรวจยอดในระบบ vs ของจริงที่หน้าชั้น
ใช้เวลา: 15–30 นาที
บันทึก: เฉพาะรายการที่ไม่ตรง
```

### 2. นับรายสัปดาห์ (Weekly Count)
```
ใครนับ: หัวหน้าคลัง + พนักงาน
นับอะไร: สินค้าหมวดที่หมุนเวียนเร็ว (แอร์ / ทีวี / เครื่องเล็ก)
วิธี: นับกายภาพแต่ละรุ่น
ใช้เวลา: [TBD] ชั่วโมง
เปรียบเทียบกับ: ยอดในระบบ
```

### 3. นับรายเดือน (Monthly Count)
```
ใครนับ: ทีมคลัง + ตัวแทนบัญชี (แยกกัน)
นับอะไร: สินค้าทุกรายการ
วิธี: นับ 2 รอบอิสระ แล้วเปรียบเทียบ
ใช้เวลา: [TBD] วัน
ส่งรายงานให้: หัวหน้า + บัญชี + ผู้บริหาร
```

### 4. นับประจำปี (Annual Physical Inventory)
```
นับทุกรายการ ทุกคลัง ทุก S/N
ปิดการเบิก-จ่ายชั่วคราวระหว่างนับ [TBD: กี่วัน]
ผลการนับใช้เป็นฐานยอดต้นปีถัดไป
```

## SOP การนับสต็อก (Step by Step)

### ขั้นที่ 1: เตรียมก่อนนับ
```
  □ พิมพ์ Stock List จากระบบ (ยอดตามระบบ)
  □ จัดเรียงสินค้าให้พร้อม (ดูหัวข้อ 02-storage-layout.md)
  □ แยกสินค้าพักรอ/ค้างตรวจออกก่อน (ไม่นับรวม)
  □ แยก Display ออกก่อน (นับแยก)
  □ แจ้งทีมขาย: "ระหว่างนับ ห้ามหยิบสินค้าออก"
  □ หยุดรับสินค้าระหว่างนับ (ถ้าเป็นไปได้)
```

### ขั้นที่ 2: วิธีนับ
```
หลักการนับ:
  "นับทีละรุ่น ทีละโซน ทีละชั้น"
  ไม่กระโดดข้ามรุ่นหรือโซน

ขั้นตอน:
  1. เริ่มจากโซน A → B → C ตามลำดับ
  2. นับทีละแถว ซ้ายไปขวา บนลงล่าง
  3. ทำเครื่องหมายที่นับแล้ว (กากบาท / สติ๊กเกอร์)
     เพื่อไม่ให้นับซ้ำหรือตกหล่น
  4. บันทึกจำนวนในแบบฟอร์ม (ไม่ใช่ในใจ)
  5. สินค้าที่มี S/N → สแกน หรือจดทุกตัว
```

### ขั้นที่ 3: นับ 2 รอบ (กรณีนับรายเดือน/รายปี)
```
รอบที่ 1: ทีม A นับและบันทึกอิสระ
รอบที่ 2: ทีม B นับและบันทึกอิสระ (ไม่ดูผล A)
เปรียบเทียบ:
  ตรงกัน → ยืนยันยอด
  ต่างกัน ≤ 1 ชิ้น → นับรอบที่ 3 เป็นการตัดสิน
  ต่างกัน > 1 ชิ้น → นับใหม่ทั้งรุ่น
```

### ขั้นที่ 4: เปรียบเทียบกับระบบ
```
ยอดจริง vs ยอดในระบบ:
  ตรงกัน → ปิดการนับ บันทึกผล
  ไม่ตรง → ตรวจสอบก่อนปรับ:
    □ มีรายการรับ/จ่ายที่ยังไม่บันทึกในระบบไหม?
    □ สินค้าอยู่ผิดโซนไหม?
    □ S/N สลับกันไหม?
    □ ถ้าหาสาเหตุไม่ได้ → บันทึก Variance และรายงาน
```

### ขั้นที่ 5: บันทึกผลและรายงาน
```
บันทึกในระบบ [Hero/Dynamics — TBD]:
  □ ยอดจริงที่นับได้ (แยกรุ่น)
  □ Variance (ส่วนต่างจากระบบ)
  □ เหตุผล (ถ้าทราบ)

รายงานต้องมี:
  □ วันที่นับ
  □ ผู้นับ (ชื่อ 2 คนขึ้นไป)
  □ รายการที่มี Variance
  □ มูลค่า Variance รวม
  □ ลายเซ็นหัวหน้าคลัง + ตัวแทนบัญชี
```

## การนับสินค้าพิเศษ

### นับแอร์ (มี 2 ชิ้น/ชุด)
```
  □ นับเป็นชุด (1 Indoor + 1 Outdoor = 1 ชุด)
  □ ตรวจว่า S/N คู่ถูกต้อง
  □ ถ้าพบ Indoor ไม่มีคู่ Outdoor → รายงานทันที
```

### นับ Display
```
  □ นับแยกจากสต็อกปกติ
  □ บันทึก: S/N / รุ่น / วันที่เริ่มโชว์ / สภาพ (A/B/C)
  □ สภาพ A = ดีมาก / B = มีรอยเล็กน้อย / C = มีรอยชัดเจน
  □ เปรียบเทียบกับบันทึกครั้งก่อน — มีสภาพแย่ลงไหม?
```

### นับอะไหล่
```
  □ นับตาม Part Number
  □ แยกอะไหล่ดี vs อะไหล่เสีย
  □ อะไหล่เสียไม่นับรวมยอดปกติ
```

## สัญญาณเตือนที่ต้องรายงานทันที

```
🚨 รายงานหัวหน้าทันที เมื่อ:
  → Variance > [TBD] ชิ้น หรือ > [TBD] บาท
  → S/N ในระบบไม่ตรงกับตัวสินค้า
  → สินค้าหายไปโดยไม่มีเอกสารการจ่าย
  → พบสินค้าที่ไม่มีในระบบ (สินค้าผีสินค้าหมอก)
  → Display หายหรือถูกนำออกไปโดยไม่มีบันทึก
```
