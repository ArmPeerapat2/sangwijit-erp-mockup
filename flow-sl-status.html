1

สายขายหลัก (SL-1 → SL-2 → SL-3 → SL-4 → waterfall WH → รับเงิน)

ขายสดข้าม 1.1-1.4 เปิดบิลตรงที่ 1.5 ได้
ขั้นงานถัดไปเซลล์ผู้อนุมัติคลัง/บัญชีสถานะจะเปลี่ยนเป็นSurface
1.1เมนูขาย: สร้าง ใบเสนอราคา หรือ ใบสั่งขาย ได้ (S1) — ค้นลูกค้า (sc1) + สินค้า (sc2) · ดูราคา + สต๊อกเบื้องต้นตอนคีย์→ 1.2สร้าง/แก้——ร่างF·SL-1
1.2ยืนยันใบเสนอ 🔒 เกินวงเงิน/ต่ำกว่า floor → สาย 2 · หมดอายุ auto 30 วัน→ 1.3ส่งยืนยัน(ติด gate → สาย 2)—รอสั่งซื้อF·SL-1
1.3แปลงเป็นใบจอง — กันสต๊อก BC ทันที + ตั้งอายุ (7/15/30 วัน) · สต๊อกไม่พอ → ลิสต์ใบจองที่ถือของ + ขอถอนจอง→ 1.4Confirm ใบจอง——Confirmed · กันสต๊อก✓ หมดอายุ=ปล่อยคืน autoF·SL-2 · P3/P4
1.4รับมัดจำ — หลายงวดได้ (sc-payment) → Post ลง Customer Ledger→ 1.5รับเงิน+Post—บัญชีเห็น GLมัดจำ Posted · รอหักบิลF·SL-3 · P2
1.5เปิดบิลขาย — หักมัดจำอัตโนมัติ · โปร auto-match · เลือกรับเอง/จัดส่ง/ติดตั้ง 🔒 เครดิตเกิน → สาย 2→ 1.6คีย์บิล(ติด gate → สาย 2)—ร่าง · รอ PostF·SL-4
1.6Post บิล → BC (VAT + AR) · waterfall auto-gen ใบขอเบิกต่อบรรทัด (WH-2R) · ติดตั้ง → เปิดงาน SV→ 1.7 + WHPost—คลังเห็นตั๋ว WH-Q2Posted · แจ้งคลังเบิกF·SL-4
1.7รับเงิน — สด/QR/บัตร จบที่บิล · เครดิต → รอ FI-1 รับชำระจบ / FI-1รับเงินสด—บัญชีรับเครดิตที่ FI-1ชำระแล้ว 💬 / ค้างชำระP2 · FI-1
2

สายอนุมัติวงเงิน SL-F1

แตกจาก 1.2 / 1.5 หรือทุกจุดที่เกิน · tier CF-2.6 · SLA 4 ชม.
ขั้นงานถัดไปเซลล์ผู้อนุมัติ (tier CF-2.6)สถานะจะเปลี่ยนเป็นSurface
2.1ระบบจับ 3 เหตุ: เกินวงเงิน / ค้างเกิน term / ต่ำกว่า floor → เซลล์กรอกเหตุผล + ส่งคำขอ→ 2.2กรอกเหตุผล 1 ช่อง—รออนุมัติวงเงินP1 💬S2
2.2ตั๋วเข้าคิวอนุมัติ — tier ตามยอดเกิน · Maker≠Checker · เกิน SLA → escalate→ 2.3/2.4ดูสถานะได้เปิดดูวงเงิน/ประวัติชำระรออนุมัติA2
2.3อนุมัติ → เปิดวงเงินชั่วคราว (มีวันหมดอายุ) → เอกสารต้นทางปลดล็อก↩ สายเดิมไปต่อได้อนุมัติ + เงื่อนไขApprovedA2
2.4ปฏิเสธ — บังคับกรอกเหตุผล → ตีกลับให้เซลล์แก้↩ 1.1/1.5แก้เอกสารปฏิเสธ + เหตุผลตีกลับเป็น OpenA2
3

สายใบลดหนี้ SL-CN

2 ทางเข้า (จากบิล / คำขอจากเคลม SV) → อนุมัติทุกใบ → ของก่อนเงิน → Post → FI-1Q
ขั้นงานถัดไปเซลล์/แอดมินขายผู้อนุมัติคลัง/บัญชีสถานะจะเปลี่ยนเป็นSurface
3.1คำขอ CN เกิด — จากบิล SL-4 Posted / SV-4 ส่งคำขอเข้า SL-Q กลุ่ม CN (badge 🛠️ + อ้าง ARI)→ 3.2เห็นตั๋วในคิว——คำขอรอเปิดใบ 💬A1·SL-Q
3.2เปิดฟอร์ม SL-CN — โหมด ✏️ปรับราคา / 📦คืนบางรายการ / ↩️คืนทั้งบิล · เหตุผลล็อกถ้ามาจากเคลม→ 3.3กรอก + เลือกโหมด——ร่างF·SL-CN
3.3ส่งอนุมัติ 🔒 CF-2.6 ทุกใบ ไม่มียกเว้น (กัน fraud ซอยใบเล็ก)→ 3.4รอผลอนุมัติ/ตีกลับ—รออนุมัติA2 💬S3
3.4🔒 ของก่อนเงิน — โหมดคืนของ: รอ WH รับของคืน (ผ่าน WH-Q1/WH-1) · จากเคลม = ใช้หลักฐานรับตอน intake · ปุ่ม Post disable จนครบ→ 3.5รอ—คลังรับของคืนอนุมัติแล้ว · รอรับของคืนF·SL-CN + WH-Q1
3.5Post CN → ลด AR + ปรับ VAT · เครดิตค้างใน Customer Ledger — CN ห้ามสั่งเงินออกเอง→ 3.6Post—บัญชีเห็นเครดิตค้างPosted · เครดิตค้างF·SL-CN
3.6ใช้เครดิต = ขั้นแยกที่ FI-1Q — หักบิลถัดไป / คืนเงินสด (Finance + approval · refund ≤ ราคาขายเดิม)จบ—อนุมัติจ่ายคืนFinance ทำรายการเครดิตถูกใช้ / คืนเงินแล้ว 💬FI-1Q
✅ S1เมนูขาย = สร้าง ใบเสนอราคา หรือ ใบสั่งขาย ได้ · ใช้ ดูราคา + สต๊อกเบื้องต้นตอนคีย์ (ผูก SC-2 ค้นสินค้า)
✅ S2เอกสารติดวงเงิน = เด้ง popup ในฟอร์ม กรอกเหตุผลแล้วส่ง (ไม่หลุดจากงาน)
✅ S3อนุมัติ SL-CN = รวมจอเดียวกับอนุมัติวงเงิน (SL-F1/AP-1 คิวอนุมัติงานขายที่เดียว)
✅ S4โชว์ — SL-Q อ่านสถานะ "ค้างชำระ/ชำระแล้ว" ข้ามมาให้เซลล์เห็น (read-only)
4

สายคอมมิชชั่นเซลล์ (CM) — ปิดรอบ → คำนวณ → อนุมัติ → จ่าย

4 ชั้น (เป้าทีม+หมวด+รายตัว+ทักษะ) · จุดเดียวที่ cm1
ขั้นงานถัดไประบบ / เซลล์ผจก.ขายบัญชี (payroll)สถานะจะเปลี่ยนเป็นSurface
C1ปิดรอบเดือน — ระบบดึงยอดขาย + ยอดเก็บเงินจริงของแต่ละเซลล์เข้ารอบ→ C2ระบบดึงอัตโนมัติ——รอคำนวณคอมA·cm1
C2คำนวณคอม 4 ชั้น: เป้าทีม (base 2%) + หมวดเร่ง (+0.5% แอร์) + เกินเป้ารายตัว (+0.3%) + โบนัสทักษะ (ขายประกัน/ติดตั้ง/bundle)→ C3ระบบคำนวณ——ร่างคอม (รอตรวจ)A·cm1
C3ตรวจ + หักคืน (clawback) — บิลถูก CN/ยกเลิก/กลายเป็นหนี้สูญ → ดึงคอมคืน→ C4—ผจก.ขายตรวจ+ปรับ—รออนุมัติA·cm1
C4อนุมัติจ่ายคอม 🔒 CF-2.6 · Maker≠Checker→ C5รอผลอนุมัติ/ตีกลับ—อนุมัติแล้วAP-1
C5ส่งจ่าย → เข้า payroll / ตั้งเบิกจบ——จ่ายผ่านเงินเดือนจ่ายคอมแล้ว 💬A·cm1 → payroll
✅ S5CM แสดงเป็นรายงานสรุป — ไม่ใช่ flow เดินเอกสาร (เคาะ 2026-07-12) · ตารางบนคือ logic เบื้องหลังให้ dev เข้าใจการคำนวณ · ผู้ใช้เห็นเป็นรายงาน (ยอดคอม 4 ชั้น + clawback หักคืน) ในศูนย์รายงาน RP-1 / cm1

สายพิเศษ — Edge cases (ยกเลิก / แก้ / พิมพ์ซ้ำ)

dev ต้องรู้ว่าทำได้/ไม่ได้ · กันของ-เงินหาย
รหัสuse caseวิธี / กติกาสถานะ / ปลายทาง
SL-V1ยกเลิกใบก่อน Post (เสนอ/จอง/บิลร่าง)กดยกเลิก + เหตุผล · ใบจอง = ปล่อยสต๊อกคืนทันทียกเลิกแล้ว
SL-V2บิล Post แล้วต้องแก้/คืน❌ ห้ามแก้บิลตรง → เปิด SL-CN (สาย 3) reverse + ออกใหม่→ สาย 3
SL-V3ใบเสนอ/ใบจอง แพ้งาน หรือ หมดอายุปิดเป็น Lost / Expired · จอง = ปล่อยสต๊อก (auto)Lost / Expired
SL-V4คืนมัดจำที่ไม่เกิดการขายยกเลิกจอง → คืนมัดจำผ่าน FI (ต้อง approval)คืนมัดจำแล้ว
SL-V5พิมพ์เอกสารซ้ำ (reprint)พิมพ์ซ้ำได้ · ลง audit log (ใคร/เมื่อไหร่/กี่ครั้ง)ไม่เปลี่ยนสถานะ
