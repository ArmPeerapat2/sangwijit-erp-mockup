1

สายซื้อหลัก (PR → อนุมัติ → PO → รับของ → ตั้งหนี้ → จ่าย)

MOS critical / แผนก·สาขาขอเอง
ขั้นงานถัดไปผู้ขอ/สาขาจัดซื้อผู้อนุมัติคลังบัญชี/การเงินสถานะจะเปลี่ยนเป็นSurface
1.1สร้างใบขอซื้อ PR — เช็ค MOS ต่อบรรทัด (🔴≤2 ต้องสั่ง · 🟢>4 เตือนห้ามสั่ง)→ 1.2สร้าง PRสร้างแทนได้———ร่างF·PO-1
1.2ส่งขออนุมัติ — tier CF-2.6 · Maker≠Checker→ 1.3รอผล—อนุมัติ/ตีกลับ——รออนุมัติP1 💬Q3
1.3อนุมัติแล้ว → เข้าคิวรอสั่งซื้อ→ 1.4เห็นสถานะเห็นตั๋วในคิว———อนุมัติแล้ว · รอสั่งซื้อA1·PO-Q
1.4เปิดใบสั่งซื้อ PO-4 — ราคา/ส่วนลดดึงจากข้อตกลง PO-2 → ส่งขออนุมัติ PO→ 1.5—สร้าง POอนุมัติ PO——รออนุมัติF·PO-4 + P1
1.5Send PO ให้ Vendor + พิมพ์→ 1.6—ส่ง Vendor—เห็นตั๋วรอรับ WH-Q1—ค้างรับ (รอของ)F·PO-4
1.6รับของจริงที่ WH-1 (ทยอยรับได้) — ฝั่ง PO เห็น % รับสะสม read-only→ 1.7—เห็น % รับ—รับ + Post GRN🔒 รับครบบิล → ปลดล็อกตั้งหนี้รับบางส่วน → รับครบWH-Q1/WH-1
1.7ตั้งหนี้ PO-6 — 3-Way Match · ราคาต่างเกิน 5% ต้องอนุมัติพิเศษ · ดึงรายการหัก PO-CN/PO-7 จากคิวรอหัก→ 1.8————สร้าง + Post APตั้งหนี้แล้ว · ค้างชำระF·PO-6 + P2
1.8จ่ายชำระที่ FI-2 (หัก WHT → cert ที่ FI-12)จบ————จ่าย + WHTจ่ายแล้ว → ปิดรายการFI-2/FI-12
2

สายสั่งซื้อสินค้าฝาก PO-8

ดิวเครดิตถึงแต่ของยังไม่ครบ · bypass GRN gate · 2-Way Match
ขั้นงานถัดไปจัดซื้อคลังบัญชี/การเงินสถานะจะเปลี่ยนเป็นSurface
2.1ดิวถึง + PO ยังรับไม่ครบ → แจ้งเตือนในคิว→ 2.2เห็นตั๋วเตือน—เห็นด้วยดิวถึง · ของยังไม่ครบ 💬A1·PO-Q
2.2สร้างบิลฝาก PO-8 อ้าง PO — เลือกสถานการณ์ A (ยังไม่รับเลย) / B (รับบางส่วน)→ 2.3สร้าง——ร่าง 💬F·PO-8
2.3Post จ่ายล่วงหน้า — PO-6 โหมดบิลฝาก (2-Way · ข้าม GRN gate) · GL: Dr.Advance/Cr.Bank→ 2.4——Post + จ่ายจ่ายแล้ว (บิลฝาก)F·PO-6 โหมดฝาก
2.4ทยอยรับของตามรอบส่ง — จ่ายออกจากกองของ Vendor + ผูก S/N→ 2.5ติดตามค้างรับรับ WH-1 + S/N—มีของในกอง · จ่ายออก X%F·PO-8
2.5ของครบ → Settle: ล้าง Advance + ตั้งหนี้จริง (3-Way ตรวจย้อนหลัง) · ค้างรับ >60 วัน → เตือน ผจก.+การเงินจบแจ้งของครบ—Settle 💬Q4เคลียร์จบ (Settled) 💬F·PO-8
3

สายส่งเสริมการขายฝั่งซื้อ (PO-2 ข้อตกลง → PO-7 realize → หักที่ PO-6)

⚠️ ไม่มีผลภาษีจนกว่า Realize · จุดจ่ายเดียว = PO-7
ขั้นงานถัดไปจัดซื้อเซลล์ Vendorบัญชี/การเงินสถานะจะเปลี่ยนเป็นSurface
3.1บันทึกข้อตกลง PO-2 (1 ใบ/1 ประเภท) + ระดับหลักฐาน 🗣️รับปาก → 📄มีเอกสาร → ✍️เซ็นแล้ว→ 3.2สร้าง + แนบหลักฐานเซ็นรับทราบ—ร่าง → รอเซ็น → ใช้งานF·PO-2
3.2ตั้งยอดรอเก็บที่ PO-7 — อ้าง PO-2 · รับปาก=ตั้งได้แต่ติดธง 🟡 เสี่ยง→ 3.3ตั้งยอด—FI-8 เห็น read-onlyตั้งยอดรอเก็บ (Accrued) 💬Q1F·PO-7
3.3ได้ CN/Invoice จากห้าง — ตรวจ CN Audit 7 ข้อ · ช้าเกิน Day-30 → STOP NEW PO→ 3.4แนบ + ตรวจส่งเอกสาร—ได้เอกสารแล้วF·PO-7
3.4Confirm & Realize 🔒 จุดรับรู้จุดเดียวที่ PO-7 (FI-8 ห้ามมีปุ่มจ่าย) · GL impact เกิดตรงนี้→ 3.5ผจก.กด Confirm—เห็นยอดเข้าคิวหักเก็บได้จริง (Realized)F·PO-7 + P1
3.5ยอดเข้าคิวรอหัก → PO-6 ดึงไปหักตอนตั้งหนี้ / FI-2 offsetจบ——ดึงหักใน pickerหักหนี้แล้ว · ปิดยอด 💬P2 (ใน PO-6)
3.xทางแยก: ครบงวด → หมดอายุ · MD ยกเลิก → Cancelledจบ———หมดอายุ / ยกเลิกF·PO-2
4

สายลดหนี้เจ้าหนี้ PO-CN

คืนของ / ราคาผิด / เคลม (CLM→PCN · SV ไม่ออกเอกสารบัญชีเอง)
ขั้นงานถัดไปต้นทาง (คลัง/ช่าง)จัดซื้อผู้อนุมัติบัญชี/การเงินสถานะจะเปลี่ยนเป็นSurface
4.1คำขอเกิด — โหมดคืนสินค้า / ลดราคา / เคลม · อ้างบิลเดิม GRN/AP/PO→ 4.2ส่งคำขอ/แจ้งเหตุสร้าง PCN + เลือกโหมด——ร่างF·PO-CN
4.2กรอกรายการลดต่อบรรทัด + เลข CN ของ Vendor→ 4.3—กรอก + แนบ CN💬Q2 มีขั้นอนุมัติไหม—ร่าง · พร้อม PostF·PO-CN
4.3Post ลดหนี้ — Dr.เจ้าหนี้/Cr.สินค้า+ภาษีซื้อ · โหมดคืนของ → คลังตัดสต็อก→ 4.4คลังตัดของออกPost—เห็นยอดรอหักรอหักหนี้F·PO-CN
4.4PO-6 ดึงตัดยอดใน picker → AP ลด → FI-2 จ่ายสุทธิจบ———ดึงหัก + จ่ายสุทธิหักหนี้แล้ว 💬P2 (ใน PO-6)
💬 Q1สถานะฝรั่งสาย 3 (Accrued/Realized/Settled) แปลไทยไหม? — ก. ไทยนำ+วงเล็บอังกฤษ: "ตั้งยอดรอเก็บ (Accrued) · เก็บได้จริง (Realized) · เคลียร์จบ (Settled)" (แนะนำ — ตามกฎไทยนำ) · ข. คงอังกฤษ · ค. ไทยล้วน
💬 Q2PO-CN ต้องผ่านอนุมัติก่อน Post ไหม? — ตอนนี้ mockup กด Post ได้เลย แต่ฝั่งขาย SL-CN เคาะ "อนุมัติทุกใบ" · ก. อนุมัติทุกใบเหมือน SL-CN (แนะนำ — ใบลดหนี้=เงินหาย เจ็บพอกัน · กติกาเดียวกันจำง่าย) · ข. เฉพาะเกินวงเงิน (tier) · ค. ไม่ต้อง (มี CN vendor เป็นหลักฐาน)
💬 Q3กดอนุมัติ PR/PO ที่ไหน? — ก. popup จากคิวกลาง AP-1 เหมือน WH-5 + ลิงก์เปิดใบเต็ม (แนะนำ — ผู้อนุมัติเห็นงานค้างที่เดียว) · ข. เปิดหน้าเอกสารเต็มเท่านั้น · ค. ได้ทั้งสองทาง
💬 Q4ปุ่ม Settle บิลฝาก (2.5) ใครถือ? — ก. การเงินเท่านั้น จัดซื้อแจ้ง "ของครบ" (แนะนำ — Maker≠Checker · จัดซื้อไม่ปิดตัวเลขที่ตัวเองสั่ง) · ข. ผจก.จัดซื้อกดได้ด้วย (spec เดิม)
