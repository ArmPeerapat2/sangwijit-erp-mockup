🗺️ Workflow Map — 7 สายหลักของระบบ

Sangwijit ERP Portal · อัพเดท 2026-07-03: WH renumber (เบิก=WH-2 · โอน=WH-3) + waterfall + kitchen rail + นับสต๊อก · เดิม audit 17/17 (2026-07-02) · คู่กับ SKILL.md § Cross-Module Flow Rules

SL งานขาย PO จัดซื้อ WH คลัง FI บัญชี SV บริการ ⭐ OWNER = จุดเดียวที่สร้าง/สั่งได้ · GATE = เงื่อนไขบังคับก่อนไปต่อ

1. สายขาย (Order-to-Cash)

เสนอราคา → จอง → มัดจำ → บิล → เบิก → ส่ง+ติดตั้ง
SL-1ใบเสนอราคา
เกินวงเงิน → SL-F1 ผ่าน CF-2.6
→
SL-2ใบจองreserve BC · อายุใบจองระบุได้/default · หมดอายุปล่อยคืนอัตโนมัติ
→
SL-3ใบมัดจำ (ขาย มัดจำ)ลูกค้าจ่ายล่วงหน้า · หักบิลอัตโนมัติ
→
SL-4บิลขายBill-to = ที่อยู่ใบกำกับ ≠ Ship-to = ที่อยู่ส่งของ
→
WH-2เบิกออกผ่านคำขอ WH-2R + คิว WH-Q2 · Serial กรอกที่นี่ที่เดียว
→
SV-6จัดส่ง+ติดตั้งอ่านที่อยู่จาก Ship-to เท่านั้น
⬇ WATERFALL
ยืนยันขาย + ระบุคลังจ่าย → auto สร้างใบขอต่อบรรทัดตามลำดับ: เบิก (คลังจ่าย WH-2R) → โอน (คลังอื่น WH-3R) → ซื้อ (PO) · กันสต๊อกทันที · ขึ้นคิวเบิก WH-Q2 เมื่อแพลนวัน (ดูสาย 6)
↩ CN LOOP
บิล Post แล้วต้องแก้ → SL-CN ใบลดหนี้ เท่านั้น (ดูสาย 3) — ห้ามแก้บิลตรง · Post ไปแล้ว Reverse+สร้างใหม่
🔒 สต๊อกไม่พอตอนจอง → แสดงลิสต์ใบจองที่ถือของ (เลขใบ+เซลล์+วันหมดอายุ) ไปคุยถอนจอง 💰 เงินเข้า: FI-1 รับชำระ · เครดิต/มัดจำ apply ที่ FI-1Q

2. สายซื้อ (Procure-to-Pay)

ขอซื้อ → สั่งซื้อ → รับของ → ตั้งหนี้ → จ่าย
PO-1ใบขอสั่งซื้อ
อนุมัติตาม tier CF-2.6
→
PO-4ใบสั่งซื้อ
→
WH-1รับเข้าคลัง (GRN)ทยอยรับ/รับทั้งบิล · ลง Serial+Bin · Post ครั้งเดียว
GATE: รับครบบิล → ปลดล็อกตั้งหนี้
→
PO-6ตั้งหนี้เจ้าหนี้3-Way Match · picker ดึงใบแจ้งหนี้ + ลดหนี้/หัก 4 หมวด
→
FI-2จ่ายชำระ APหัก WHT → เข้า pending FI-12
🟣 BYPASS
PO-8 สั่งซื้อสินค้าฝาก (เดิม "บิลฝาก") — vendor วางบิลก่อนรับของครบ → PO-6 โหมด Deposit ข้าม GRN gate · 2-Way Match · Settle เมื่อของครบ
↩ AP ลดหนี้
PO-CN ใบลดหนี้ซื้อ (คืนของ/ราคาผิด/เคลม vendor) + PO-7 ส่งเสริมการขาย (⭐ จุดจ่ายเดียว — Realize แล้วส่งเข้า PO-6 · FI-8 ดูอย่างเดียว) → หักยอดใน PO-6 picker
🔒 Sell-out rebate: serial จาก itemLedger (WH-3) ผูกกลับ SL-4 · ไม่มีบิล → tab "Serial ไม่มีบิลอ้างอิง" ผูกย้อนหลัง ⚠️ Dual-Book: ทุก AP Invoice ต้องมี Entity Tag

3. สายเคลม → ใบลดหนี้ (grill Q1-Q10)

claim = ประเภทงานใน SV · ไม่ใช่ module แยก
SVService Intake (งานเคลม)รับของเข้าตอน intake = หลักฐานรับของคืน
→
SVตัดสินเคลม — ผลจบ 3 ทาง
① ซ่อมเสร็จ
จบใน SV — ไม่แตะเอกสารเงิน
② เปลี่ยนตัวใหม่
จบใน SV/WH (เบิกเครื่องใหม่) → ไล่ vendor ผ่าน CLM → PO-CN — ไม่ออก SL-CN (เงินลูกค้าไม่เกี่ยว)
③ คืนเงิน/ลดหนี้
ส่งคำขอเข้า SL-Q กลุ่ม CN (badge 🛠️ จากเคลม SV) → Sales เปิด SL-CN prefill · เหตุผลล็อก "เคลม (จาก SV)"
SL-CNใบลดหนี้ขาย3 โหมด: ปรับราคา / คืนบางรายการ / คืนทั้งบิล · รูปแบบเอกสาร auto ตามบิลต้นทาง
GATE 1: อนุมัติ CF-2.6 ทุกใบ
→
GATE 2: โหมดคืนของ = รอรับของคืนก่อนเท่านั้น
→
POSTลด AR + ปรับ VATเครดิตค้างใน Customer Ledger
→
FI-1Qใช้เครดิต (ขั้นแยก)หักบิลถัดไป (apply) / คืนเงินสด (Finance + approval)
⛔ ห้าม CN สั่งเงินออกเอง — Maker≠Checker 🔒 SV ไม่ออกเอกสารบัญชี — ส่งคำขอเท่านั้น (pattern เดียวกับ CLM→PO-CN)

4. สายโอนคลัง (Transfer)

WH-3R ขอโอน → WH-3 โอน (owner) → WH-1 รับ
WH-3Rขอโอน (Transfer Request)ฟอร์มคำขอ · ไม่มี "จำนวนที่ได้จริง" · ไม่สร้างใบโอนเอง
→
WH-3โอนสินค้าจุดเดียวที่สร้าง TO · มี "จำนวนที่ได้จริง" · Draft→Shipped→In-Transit
In-Transit ไม่นับสต๊อกทั้ง 2 คลัง
→
WH-1รับโอน (TR-In)match TO status=Shipped · ยืนยันรับได้ครั้งเดียว → Received
🔒 กันใบซ้อน (2 ที่สร้างไม่ได้) + กันรับซ้ำ (idempotent — สต๊อกไม่เข้า 2 เท่า)

5. สายภาษีหัก ณ ที่จ่าย (WHT)

สร้างได้ 2 ที่ · ออกหนังสือที่เดียว
FI-2จ่ายเจ้าหนี้auto-calc WHT → record pending
↘
FI-12ภาษีหัก ณ ที่จ่ายรวม pending ทั้งหมด · เรทเป็น dropdown (1/2/3/5%) · Release → Print หนังสือรับรอง + ภ.ง.ด.3/53
↗
FI-4ค่าใช้จ่าย+WHTสร้าง record เท่านั้น — ไม่มีปุ่มออกแบบ ภ.ง.ด.
⛔ FI-2/FI-4 ห้ามมีปุ่ม Print Certificate — vendor ได้หนังสือ 2 ใบ = ปัญหากรมสรรพากร Released แล้วแก้ไม่ได้ — Reverse + สร้างใหม่ (BC เป็นเจ้าของ posting)

6. สายคลังปฏิบัติการ (WH Ops · Kitchen Rail + นับสต๊อก)

คิว = รางรวมตามทิศ · R = ตั๋วขอ · action = ทำจริง
WH-Q1คิวรับ (Kitchen Rail)รวมตั๋วเข้า: รับซื้อ+รับโอน+รับคืน → คลิก→ WH-1
·
WH-Q2คิวเบิก (Kitchen Rail)รวมตั๋วออก: ขอเบิก+ขอโอน+จอง → คลิก→ WH-2/WH-3
R → ACTION
ทุกงานคลังมีคู่ ใบขอ (R) → ใบทำจริง: WH-2R ขอเบิก→WH-2 เบิก · WH-3R ขอโอน→WH-3 โอน · WH-4R เตรียมนับ→WH-4 นับ — R ต่างที่ตัดคอลัมน์ "จำนวนจริง/Variance" ออก
WH-4Rเตรียมนับเลือกคลัง/Bin/ประเภท (Cycle/Annual/Spot/Recount) + freeze snapshot
→
WH-4นับสต๊อกกรอกนับจริง → auto Variance
Variance ≠ 0 → auto Recount ให้ verify
🔒 คิว = รวมหลายเอกสารตามทิศ (ไม่ใช่ 1 คิว=1 ประเภท) · คลิกตั๋ว→เปิดฟอร์มทำจริง 🔒 กันสต๊อก (reserve) ตอนสร้างใบขอ · แก้ใบขายภายหลัง → admin ยืนยันก่อน sync

7. สายบริการ/ซ่อม (Service Ops)

รับงาน → มอบหมาย → อะไหล่ → ปิดงาน/บิล → ส่งคืน
SV-Qคิวงานซ่อมdashboard ช่าง · group by ช่าง → CM-1
→
SV-1รับงาน (intake)S/N-first · 5 job types · resolve A-E
→
SV-2มอบหมายช่าง
→
SV-3เบิกอะไหล่+ SV-Order สั่งนอกประกัน (spawn PO)
→
SV-5Job Card
→
SV-4ปิดงาน/บิลpayer รายบรรทัด → ARI(แบรนด์)/SL-4(ลูกค้า)
GATE: ค้างคืนอะไหล่ในประกัน → ปิดไม่ได้
→
SV-7ส่งคืนลูกค้า
① เคลมสินค้า
ของเราซื้อมาเสีย → ส่งคืน vendor ทั้งชิ้น → CLM → PO-CN (S1-S4) · pre-sale (ไม่มีลูกค้า) เข้าทางนี้
② เคลมงานบริการ
ของอยู่กับลูกค้า ในประกันแบรนด์ → ซ่อม/เปลี่ยนอะไหล่ · payer split: แบรนด์→ARI · ลูกค้า→SL-4 · goodwill = payer option ที่ 3
🔒 ประกัน per-component (แอร์ 1 ปี · คอมเพรสเซอร์ 5 ปี) → ตารางประกันรายชิ้น 🔒 รายได้ 3 อย่าง: ค่าแรง/อะไหล่/เดินทาง · คนจ่ายรายบรรทัด (default จากประกัน · admin override) ↩️ อะไหล่ในประกันต้องคืนของเก่าให้แบรนด์ (per-line gate) · นอกประกันซื้อขาดไม่คืน
